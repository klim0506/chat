# Безопасность чатов и аккаунта

Ответы на вопросы о **безопасности платформы приватных чатов**: как происходит вход (без пароля, по коду), кто может видеть чаты, как защищены файлы и можно ли «найти чат в поиске». Информация для запросов вроде «безопасность мессенджера», «вход без пароля», «кто видит чаты».

---

## Как войти в аккаунт: без пароля, по коду

Вход в платформу — **только по номеру телефона**. Пароль не используется.

1. Вы вводите **номер телефона** на странице входа.
2. На этот номер отправляется **одноразовый код** (несколько цифр).
3. Код может прийти:
   - **в Telegram** (через шлюз/бота платформы), если у вас привязан Telegram и это настроено;
   - **по SMS** (через провайдера, например RedSMS), если выбран способ «SMS» или Telegram недоступен.
4. Вы вводите код в форму входа — и получаете доступ. Сессия хранится в виде токенов (JWT); пароль нигде не хранится.

Так снижаются риски утечки пароля и перебора паролей. Для защиты от злоупотреблений действуют **ограничения частоты запросов**: с одного IP ограничено количество запросов кода и попыток ввода кода в минуту.

---

## Кто может видеть чаты и как попасть в чат

- **Список чатов** видит только авторизованный пользователь и только **те чаты, в которых он участник**. Нет общего «поиска чатов по имени» для всех пользователей.
- Попасть в чат можно **только по пригласительной ссылке** с правильным кодом. Ссылка содержит идентификатор чата (slug) и криптографически подписанный код; без этой пары присоединиться к чату нельзя.
- То есть чаты **приватные по умолчанию**: их не видно в поиске, в них нельзя зайти «с улицы» — только по ссылке, которой поделился владелец или участник.

---

## Как защищены файлы и медиа

- **Загрузка файлов** доступна только **авторизованным** пользователям. Если файл привязан к чату, сервер проверяет, что пользователь является участником этого чата.
- **Скачивание и просмотр** загруженных файлов — по **временной подписанной ссылке** (токен с ограниченным сроком жизни и криптографической подписью). Постоянные прямые ссылки «в открытый доступ» не выдаются, что ограничивает утечку и неконтролируемое распространение.

---

## Сессии и токены (кратко для продвинутых)

После ввода кода выдаётся пара **JWT**: access-токен (для API и WebSocket) и refresh-токен (только для обновления access). Refresh-токен **не принимается** вместо access при обращении к API — это проверяется на сервере. На обновление токена также действует ограничение частоты запросов (rate limit).

---

## Что делает платформа для безопасности

- **Ограничение частоты запросов** на критические действия: запрос кода входа, ввод кода, обновление токена, при необходимости — платёжные webhook.
- **Проверка зависимостей** на известные уязвимости (например, pip-audit для backend, npm audit для frontend).
- **Тесты безопасности**: проверка JWT, rate limit, токенов доступа к файлам, валидации платёжных уведомлений.

Итог: вход без пароля по одноразовому коду (SMS/Telegram), доступ в чаты только по пригласительной ссылке, файлы по подписанным временным ссылкам и ограничения по частоте запросов снижают риски несанкционированного доступа и перебора.

---

## Частые вопросы: безопасность

**Безопасно ли входить без пароля?**  
Вход по одноразовому коду на ваш номер телефона не требует хранения пароля и снижает риск перебора. Код действует короткое время; запросы кодов ограничены по частоте с одного IP.

**Может ли кто-то найти мой чат в поиске?**  
Нет. Чаты не индексируются в общем поиске. В чат можно попасть только по пригласительной ссылке, которой вы или участники поделились.

**Кто видит мои переписки?**  
Сообщения видят только участники чата. Сервер обеспечивает доставку и хранение в рамках политики платформы; доступ к API и файлам — только по авторизации и с проверкой участия в чате.

**Как защищены загруженные файлы?**  
Доступ к скачиванию — по временной подписанной ссылке (ограниченный срок действия). Загружать файлы в чат могут только участники этого чата.
