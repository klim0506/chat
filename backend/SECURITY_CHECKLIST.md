# Что сделать только вам (пошагово)

Всё, что можно было настроить в коде и на сервере, уже сделано. Ниже — только ваши действия.

---

## 0. Проверка безопасности (рекомендуется после деплоя)

На сервере выполните один раз и при обновлении конфигов:

```bash
sudo /root/chat/scripts/harden-server.sh
```

Скрипт проверит права на `.env`, nginx-сниппеты, PostgreSQL/Redis, fail2ban, UFW и SSH; при необходимости подскажет, что включить. После изменений в `docker/nginx/` имеет смысл запустить его снова.

## 1. SSH: вход только по ключу

**В чём суть:** Сейчас на сервер можно зайти по паролю и по ключу. Злоумышленник может подбирать пароль. Нужно оставить только вход по **ключу** (файл на вашем ПК) — тогда подбор пароля бесполезен.

**Важно:** У вас уже должен быть SSH-ключ и он добавлен на сервер. Если ключа нет — сначала сделайте блок ниже «Как настроить ключ».

---

### Как настроить ключ (если его ещё нет)

Выполняйте **на своём компьютере** (Windows: PowerShell или «Терминал» в VS Code; Mac/Linux: терминал).

1. **Проверить, есть ли уже ключ:**
   ```bash
   dir %USERPROFILE%\.ssh
   ```
   (В Mac/Linux: `ls ~/.ssh`.)  
   Если есть файлы `id_ed25519` и `id_ed25519.pub` (или `id_rsa` и `id_rsa.pub`) — ключ есть, переходите к шагу 3.

2. **Создать ключ** (если нет):
   ```bash
   ssh-keygen -t ed25519 -C "ваш_email@example.com"
   ```
   На вопрос «Enter file in which to save the key» просто нажмите Enter (путь по умолчанию). Можно задать парольную фразу для ключа или оставить пустой (дважды Enter).

3. **Скопировать ключ на сервер.**
   - **Mac/Linux:** выполните `ssh-copy-id root@109.172.100.103` (пароль спросят один раз).
   - **Windows** (команды `ssh-copy-id` нет — делайте вручную):
     - В PowerShell или CMD на вашем ПК выведите ключ:
       ```bat
       type %USERPROFILE%\.ssh\id_ed25519.pub
       ```
       (Если ключ создавали как `id_rsa`, то: `type %USERPROFILE%\.ssh\id_rsa.pub`.)
     - Скопируйте **всю** выведенную строку (она начинается с `ssh-ed25519` или `ssh-rsa` и заканчивается вашим email или случайными символами).
     - Зайдите на сервер по паролю: `ssh root@109.172.100.103`.
     - На сервере выполните (одной строкой; вместо `ВСТАВЬТЕ_СТРОКУ_КЛЮЧА` — ваша скопированная строка **в кавычках**):
       ```bash
       mkdir -p ~/.ssh && echo "ВСТАВЬТЕ_СТРОКУ_КЛЮЧА" >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
       ```
       Пример: `echo "ssh-ed25519 AAAAC3Nza... klim@pc" >> ~/.ssh/authorized_keys` (ваша строка будет другой).
     - Выйдите с сервера: `exit`.

4. **Проверить вход по ключу:** закройте все сессии с сервером и зайдите снова:
   ```bash
   ssh root@109.172.100.103
   ```
   Если пароль не спросили — ключ работает. Дальше переходите к «Шаги» ниже.

---

**Шаги (отключить пароль и оставить только ключ):**

1. **Не закрывая** текущее подключение к серверу, на своём ПК откройте **второй** терминал.
2. Во втором терминале зайдите на сервер по ключу (подставьте свой ключ; часто это `~/.ssh/id_ed25519` или `~/.ssh/id_rsa`):
   ```bash
   ssh -i ~/.ssh/id_ed25519 root@109.172.100.103
   ```
   Если система запросила **пароль** — ключ не используется; не выполняйте следующие шаги, пока не настроите ключ (блок выше).
3. Если вошли **без пароля** — наберите `exit`.
4. В **первом** терминале (где вы уже на сервере) выполните:
   ```bash
   cd /root/chat && sudo ./scripts/install-ssh-keys-only.sh
   ```
   На вопрос «Continue?» введите `y` и Enter.
5. Снова зайдите по ключу из второго терминала. Если вход прошёл — пароль для SSH больше не принимается, работает только ключ.

## 2. ISPmanager (панель на порту 1501)

**Зачем:** снизить риск взлома панели.

1. Зайдите в ISPmanager.
2. Смените пароль на **сложный** (длинный, буквы + цифры + символы).
3. Включите **двухфакторную аутентификацию**, если она есть в настройках.
4. Если в панели есть «Доступ только с IP» — укажите свой домашний/офисный IP.
5. Регулярно устанавливайте обновления панели по инструкции хостинга.

---

## 3. Django Admin (админка сайта)

**Зачем:** защита от перебора пароля админки.

1. Зайдите в админку Django (вход, пользователи, модели): **https://pingychat.com/admin/** или **https://web.pingychat.com/admin/** (логин и пароль — у пользователя со статусом staff).
2. Для **каждого** пользователя со статусом «staff» установите **сложный пароль** (в админке: Пользователи → выбрать пользователя → смена пароля).

---

## 4. Пароль базы данных (на будущее)

**Зачем:** чтобы доступ к БД был только у приложения с известным паролем.

- Сейчас пароль в `DATABASE_URL` уже задан (не дефолтный). Если когда‑нибудь будете менять — задайте **длинный случайный** пароль и обновите его в `.env` и в самой PostgreSQL, затем перезапустите backend.

---

**Итог:** выполните по порядку пункты 1 → 2 → 3. Пункт 4 — по необходимости при смене пароля БД.
