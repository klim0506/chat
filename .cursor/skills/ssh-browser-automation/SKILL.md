# SSH and Browser Automation

Агент самостоятельно выполняет: SSH к серверу, запуск и управление браузером, навигацию по страницам, создание скринов и отладку по результатам.

## Принципы

1. **SSH**: выполнять команды через терминал (`ssh user@host "cmd"` или интерактивную сессию), всегда читать вывод и по нему принимать решения.
2. **Браузер**: использовать MCP cursor-ide-browser. Перед любым действием — получить состояние страницы (snapshot). Не держать браузер заблокированным дольше необходимого.
3. **Скриншоты**: `browser_snapshot` даёт структуру страницы и refs для автоматизации; для сохранения изображения в файл — запускать скрипт (см. scripts) или внешний инструмент.
4. **Отладка**: после каждого шага проверять результат (вывод терминала, snapshot); при ошибке — анализировать, менять действие и повторять. Использовать короткие ожидания (1–3 с) и повторный snapshot вместо одного долгого ожидания.

## SSH

### Подключение и выполнение команд

- **Одна команда**: `ssh user@host "command"` — дождаться вывода, проанализировать.
- **Несколько команд**: `ssh user@host "cmd1 && cmd2"` или отдельные вызовы.
- **Интерактив**: при необходимости использовать `ssh -t user@host` и передавать ввод (если окружение поддерживает).

Использовать абсолютные пути и явные переменные окружения при необходимости:
`ssh user@host "cd /app && NODE_ENV=production npm run start"`

### Отладка по SSH

- Всегда читать stdout/stderr после команды.
- При коде выхода != 0: смотреть вывод, повторить с исправлением (права, путь, зависимость, порт).
- Проверять состояние сервиса: `ssh user@host "systemctl status X"`, `ps`, `curl -s localhost:PORT`.
- Логи: `ssh user@host "tail -n 50 /path/to/log"`.

## Браузер (MCP cursor-ide-browser)

### Порядок работы

1. **Вкладки**: `browser_tabs` с action `list` — посмотреть открытые вкладки и URL.
2. **Навигация**: `browser_navigate` на нужный URL.
3. **Блокировка**: после перехода по URL вызвать `browser_lock` (lock только при уже существующей вкладке).
4. **Состояние страницы**: перед любым кликом/вводом/скроллом вызвать `browser_snapshot` — получить структуру и refs элементов.
5. **Взаимодействие**: использовать refs из snapshot для `browser_click`, `browser_type`, `browser_fill`; для ввода в contenteditable — `browser_fill`.
6. **Ожидание**: короткие паузы (1–3 с), затем снова `browser_snapshot` и проверка готовности; не полагаться на одну длинную паузу.
7. **Разблокировка**: по завершении всех действий с браузером вызвать `browser_unlock`.

Важно: нельзя вызывать `browser_lock` до `browser_navigate`; порядок — сначала навигация (или использование уже открытой вкладки), потом lock.

### Элементы и скролл

- Вложенные скролл-контейнеры: перед кликом по элементу вызывать `browser_scroll` с `scrollIntoView: true`.
- Диалоги (alert/confirm/prompt): не блокируют автоматизацию; по умолчанию confirm=true, prompt=default. Для другого поведения вызвать `browser_handle_dialog` до действия.
- Iframe: автоматизация работает только с элементами вне iframe.

## Скриншоты

- **Для автоматизации**: `browser_snapshot` — достаточно для анализа страницы и выбора элементов.
- **Файл изображения**: запускать скрипт из `scripts/` (например, Playwright/Puppeteer), передавая URL и путь сохранения. Требования к окружению и зависимости описаны в reference.md.

## Самостоятельная отладка

### Чек-лист после каждого шага

- **SSH**: код выхода команды и полный вывод в терминале прочитаны и учтены.
- **Браузер**: после навигации/клика/ввода — сделан snapshot и проверено, что страница в ожидаемом состоянии (элементы появились, нет ошибок).
- **Ошибка**: зафиксировать сообщение/вывод, предложить причину, изменить команду или действие и повторить.

### Стратегия ожидания

- Вместо одного ожидания 10+ секунд: подождать 1–3 с → `browser_snapshot` → если не готово, ещё 1–3 с → снова snapshot. Продолжать, как только контент готов.

### Терминалы

- Проверять папку терминалов (terminals): смотреть вывод последних команд и текущее состояние перед тем, как запускать новые SSH-команды или делать выводы об ошибках.

## Краткий workflow

```
SSH:
  → ssh user@host "cmd"
  → прочитать вывод, при ошибке — скорректировать и повторить

Браузер:
  → browser_tabs (list)
  → browser_navigate (если нужен новый URL)
  → browser_lock
  → browser_snapshot
  → при необходимости: короткое ожидание → snapshot (повторять до готовности)
  → browser_click / browser_type / browser_fill / browser_scroll по refs из snapshot
  → при изменении страницы: снова snapshot, затем следующие действия
  → browser_unlock

Скрин в файл:
  → вызвать scripts/capture_screenshot (см. reference.md и scripts/)
```
